5
Submission — claim sent to payer ›
Trigger
Biller clicks Submit, or system auto-submits Athelas-Responsibility claims
Form logic
CMS-1500 / UB-04 / ADA generated automatically by payer type; MSP Type Code required when Medicare is secondary/tertiary (Working Aged, ESRD, No-Fault, Workers' Comp, Black Lung, Disability, Liability)
SLA / timing
Ack. 1–3 days Processing 14–30 days Payment/denial 30–45 days Timely filing typically 60–90 days (payer-specific)
Payer response forks three ways from here: a clean acceptance goes straight to Remittance / posting; a technical rejection routes to the Rejection stage; an adjudicated-but-unpaid claim routes to the Denial stage. Both Rejection and Denial resolve either by resubmitting (rejoins Submission) or writing off (terminal, or logged as a posting adjustment).

Patient responsibility reconciliation — estimated PR trued up against remittance ›
Status names
Estimated PR → Post-Remittance PR
Three-way comparison
Payment = PR → no action  ·  Payment < PR → balance added to next statement  ·  Payment > PR → overpayment becomes a credit, locked to date of service by default
Automation
Auto-Refund — overnight process converts an overpayment into an account credit automatically
Sequencing rule
PR only reaches the patient once PR amount = total balance amount — a denied portion sitting alongside PR blocks the statement until written off or pushed

11
Patient billing / collection — statements, plans, and escalation tools ›
Trigger
PR finalized and balance > $0
Automation
Batch frequency configurable (weekly recommended); $0 balances never billed; batches spread across weekdays — ~50% of patients per batch, no more than every 14 days
Cost
Paper statements: $1 each, mailed within 24 hours, arrives in 3–5 business days
Escalation tools
Charge saved cards in bulk (min $20 / max $500 recommended) · payment plans · family combined payment · write-off · cancel PR (non-remittance-derived only)
12
Month-end close — bank tie-out and A/R roll-forward ›
Runbook
1) Bank tie-out via Bank Deposit Reconciliation Report → 2) GL entries via Revenue Activity Report → 3) Exception handling (Manual Review / unmatched deposits) → 4) A/R roll-forward
Formulas
total_cash_usd = matched_posted + matched_unposted + unmatched + others + provider_level_adjustments
Closing A/R = Opening A/R + Billed − Payments − Adjustments − Transfer Out
Aging buckets
0–30 31–60 61–90 91–120 121–180 181–365 366+ — 121–180 flagged as approaching timely filing
Exception handling
Deposit in bank but not yet in Insights → record to a clearing account, resolve next cycle (don't hold the close open)

03 Integration map

Every external system the claim lifecycle depends on end-to-end, what triggers each call, and what happens when it fails or returns bad data.

Eligibility clearinghouses

WaystarAvailityUHC Payer Portal
Triggers onAutomated check 7 days pre-visit + nightly re-check + on-demand Live Eligibility Check / Re-Run
Failure modeReturns Inconclusive or Unable to get a response — requires manual correction in the EHR and a re-run; never blocks scheduling itself

Claim submission clearinghouse

Triggers onBiller clicks Submit, or system auto-submits Athelas-Responsibility claims
Failure modeTechnical/format rejection → Rejection branch; claim is invisible to the payer until fixed and resubmitted

ERA / 835 ingestion

Triggers onPayer sends an 835 remittance file
Failure modeAmbiguous/conflicting data routes to Manual Review; duplicate or malformed data routes to Archived

Bank connection — Plaid

Triggers onPractice connects a bank account (read-only access); matching runs continuously against posted remits
Failure modeFalls into Missing ERAs / Missing Payment / Inconsistencies views; local regional banks not on Plaid are unsupported; alternate import handled by support@getathelas.com case-by-case

Virtual card processing — Stripe

Triggers onPayer issues a virtual credit card as remittance; biller manually runs "Process a Virtual Card"
Failure modeMisuse warning: never use for patient card-reader-down scenarios — pollutes revenue analytics if used for patient payments

EHR sync — bidirectional

DirectionFlow 1 AIR → Encounter (admin data); Flow 3 Encounter → AIR (billing corrections, "significant" fields only)
Never overwritesClinical documentation entered by a provider (notes, diagnoses) is never touched by administrative sync. General demographic/insurance edits made in Insights do not flow back to the EHR — only encounter-linked billing corrections do (Flow 3)

Deposit slip ingestion

Triggers onManual upload of a CSV or PDF bank deposit slip
Failure modeDUPLICATE_CHECK_NUMBER · total-mismatch rejection · content-hash duplicate block. Limits: 10MB / 3,000 rows / 800 line items

EOB Copilot

Triggers onBiller uploads an EOB PDF or screenshot for manual posting
Failure modeAI transcription lands in a review state; missing check number/date is the most common QA catch. New data visible on claims within 24 hours

✦

06 Open gaps — what the documentation didn't cover

These matter for partnership risk assessment. Nothing here is filled in with a plausible guess — if the docs didn't say it, it's listed as unknown.

01
No per-payer timely filing table
Docs state "typically 60–90 days" and flag the 121–180 day A/R bucket as "approaching" the limit — no payer-specific table is published.
02
SLA figures are softly worded
"Athelas Responsibility ~15 days" and "~24 hours" resubmission both use qualifying language ("about") — not contractually precise. Confirm exact terms in any partnership agreement rather than the docs.
03
Target Allowed Amounts (TAA) logic is opaque
Entirely Athelas-managed, "no self-serve settings screen" — actual write-off thresholds aren't documented.
04
No comprehensive CARC/RARC reference
OA23, PI-59 etc. appear as examples only — no published denial-reason-code taxonomy or the internal Unavoidable-vs-Regrettable mapping logic.
05
Rules Tab rollout status is inconsistent
Explicitly noted as "still rolling out" — not universally available across customers; gated by account manager contact.
06
"Create a Rule" is labeled Beta
Not yet live for every practice per the documentation.
07
Clearinghouse mechanics unspecified
Waystar, Availity, UHC (eligibility) and Waystar/CHC/Carisk/Availity (claims export) are named partners, but API connectivity, response-time guarantees, and failure-mode handling aren't documented.
08
Pricing model rate not disclosed
"Your Athelas Invoice" confirms billing is based on posted insurance remittances + SmartPay (text/email patient collection) transactions — the actual percentage/rate is negotiated per-practice, not public.
09
No provider enrollment / credentialing workflow found
"Provider Credentials" pages cover EHR scheduling safeguards (license/NPI tracking), not payer enrollment or credentialing as an RCM function — a notable gap since credentialing is typically core to full-service RCM.
10
Faxing / Messaging / Tasking clusters not fully fetched
These intersect with denial-appeal follow-up workflows (e.g., attaching a fax to a claim task) but weren't deeply researched — largely EHR-operational rather than billing-specific.
11
Calendar cluster out of scope
Pure scheduling mechanics — not fetched, deemed outside RCM scope.
12
"Features In Development" flags appear repeatedly
Lockbox integration, provider/claim adjustments on EOBs, interest payments on claims, cohort analysis — roadmap items, not current capability. Confirm current status directly with Athelas.
